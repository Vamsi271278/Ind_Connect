# 1. EXECUTIVE PRODUCT THESIS

People in the Indian diaspora currently rely heavily on fragmented channels such as:

- WhatsApp groups
- Telegram groups
- Facebook groups
- local associations
- community events
- dating applications
- matrimonial applications
- informal introductions

These tools solve individual pieces of the connection problem but do not provide a unified, trustworthy system for:

1. discovering relevant people nearby;
2. understanding why another person wants to connect;
3. separating friendship, community and dating intentions;
4. verifying identity;
5. controlling unwanted contact;
6. discovering local activities;
7. transitioning online discovery into meaningful offline interaction.

The V1 product will solve this problem through four core dimensions:

**Location + Intent + Interests + Trust**

The V1 experience must answer four questions for every user:

1. **Who is around me?**
2. **Why might we want to connect?**
3. **Can I trust this person enough to interact?**
4. **What can we actually do together?**

The product must not behave like a generic social feed or conventional swipe-only dating application.

# 4. PRODUCT PRINCIPLES

These rules govern every V1 product decision.

## 4.1 Intent Before Interaction

Users must understand the context of a connection before direct messaging begins.

A person seeking friendship should not unknowingly be approached through a dating context.

---

## 4.2 Consent Before Conversation

Users cannot send unrestricted private messages to strangers.

A connection request must first be accepted.

---

## 4.3 Trust Is a Product Feature

Verification, reporting, moderation and privacy are part of the core experience rather than secondary compliance features.

---

## 4.4 Approximate Location Only

The system must never publicly expose exact residential or real-time user locations.

Display geography at city/area level or approximate distance.

---

## 4.5 Local Density Over Geographic Breadth

V1 will prioritize strong activity in one metro area rather than weak activity across many cities.

---

## 4.6 Real Connections Over Engagement Tricks

The product should optimize for:

- meaningful conversations;
- accepted connections;
- event participation;
- repeat community interaction.

It should not optimize primarily for:

- endless scrolling;
- artificially inflated screen time;
- addictive swipe behavior.

---

## 4.7 Dating Is Explicitly Separated

Dating is a supported mode but must remain distinct from social/community discovery.

Users who have not opted into dating must not appear in dating discovery.

# 6. V1 SUCCESS METRICS

## Primary North-Star Metric

### Meaningful Connections Created

A **Meaningful Connection** is counted when:

1. User A sends a connection request;
2. User B accepts;
3. at least one participant sends a message;
4. the other participant responds.

The metric should not count:

- ignored requests;
- declined requests;
- unreciprocated first messages.

# 24. PERSON RECOMMENDATION LOGIC

Initial ranking should consider:

1. compatible intent;
2. proximity;
3. shared interests;
4. language overlap;
5. profile completeness;
6. verification;
7. activity recency;
8. prior interaction status.

Use deterministic scoring.

Example conceptual formula:

```text
Intent compatibility       30
Interest overlap            25
Proximity                   15
Language overlap            10
Verified profile            10
Recent activity              5
Profile completeness         5
```

Exact weights must remain configurable.

# 100. V1 USER STORY EXAMPLES

## Social Discovery

**As a new DFW resident,**
I want to find Telugu-speaking people near me who enjoy movies and dining,
so I can build a local social circle.

Acceptance:

- discovery supports compatible profiles;
- shared language visible;
- shared interests visible;
- location approximate;
- connection request available.

---

## Dating Privacy

**As a user who is not interested in dating,**
I do not want to appear to people browsing dating profiles.

Acceptance:

- Dating disabled means zero dating discovery exposure.

---

## Connection Consent

**As a user,**
I want strangers to request permission before messaging me,
so I control who can contact me.

Acceptance:

- unsolicited direct message impossible.

---

## Blocking

**As a user who feels uncomfortable,**
I want to immediately block another user.

Acceptance:

- blocked user cannot message, request or discover blocker.

**As a user interested in badminton,**
I want to see nearby badminton events,
so I can meet people through an activity.

Acceptance:

- interest/event matching works;
